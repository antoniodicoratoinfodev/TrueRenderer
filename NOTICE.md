# Dependencies and distribution status

TrueRenderer is a prototype under a **proprietary license** chosen by the owner. The text in `LICENSE` applies to the project's original code, documentation, and assets. The public repository allows inspection and the rights provided by GitHub's terms; it does not grant an open-source license. Dependencies keep their own licenses.

`Cargo.lock` pins versions and checksums. `reports/dependency-inventory.json` and `.csv` inventory the dependencies resolved for the macOS build and tests, and the notice texts available in those packages are collected in `reports/dependency-notices/`. This is a technical inventory, not an approved release bill of materials. Distribution still requires a formal SBOM, verification of the effective licenses and of the obligations for each target and channel, plus the signing and notarization foreseen in the plan.

The corpus is generated from formulas in `scripts/generate-corpus.py`, without photographs or third-party resources. The color sample values are illustrative synthetic data and do not represent certified measurements of a commercial photographic chart.

To regenerate the inventory, run `python3 scripts/dependency-inventory.py` after every change to `Cargo.lock`.

Since 0.1.3 the external macOS decoder uses ImageIO, Core Image with CIRAWFilter, and ColorSync as supplied by the operating system; those frameworks are not copied into the repository. RAW compatibility depends on the macOS version and the camera. LibRaw is not embedded in this version. The format test files are also generated by the project, without third-party photographs; `cwebp` is used solely to generate the WebP test image and is not embedded in the app.
